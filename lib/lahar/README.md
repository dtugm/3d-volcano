# Lahar/Lava Flow Simulation

Interactive flow simulation for the 3D Volcano Digital Twin. Click a Lahar Starting Point on the globe, pick a material profile and a triple-volume, watch a physics-based animation propagate downstream alongside a static LAHARZ empirical envelope.

## TL;DR — how to run it

```bash
pnpm install
pnpm dev                # http://localhost:3000
```

1. Pick **Gunung Kelud** in the left sidebar (year 2014 by default).
2. In the new **Lahar/Lava Simulation** section, choose mode = **Lahar** (or Lava).
3. Pick a material profile and edit the volume triple if you want.
4. Click on a stream on the globe — it snaps to the nearest precomputed Lahar Starting Point.
5. Press **Play**.

A full end-user walkthrough lives in the top-level [`README.md`](../../README.md#using-the-lahar--lava-flow-simulation).

## LSP click validation — four PEARPY conditions

Implemented in [`lsp-validator.ts`](./lsp-validator.ts). A click is accepted only if it:

1. **Snaps to a mainstem polyline** within 80 m (otherwise → `outside_stream`).
2. **Lies inside the proximal hazard cone** (otherwise → `below_hazard_cone`). This corresponds to the H/L energy-cone boundary in PEARPY.
3. **Falls inside the deposition polygon** (otherwise → `not_in_deposition`). In PEARPY this is the post-eruption DEM-of-Difference positive region.
4. **Snaps to the nearest precomputed LSP candidate** on that mainstem (within 150 m). Each candidate carries its supplied lahar volume triple (SLV min / likely / max).

## Models

| Aspect | Model | Reference |
|---|---|---|
| LSP and SLV extraction | PEARPY (offline, in Python) | Andaru et al. 2022 |
| Empirical inundation envelope | LAHARZ A = a·V^(2/3), B = b·V^(2/3) | Iverson, Schilling & Vallance 1998; Schilling 2014 |
| Material-dependent A, B | Custom-fit per material profile | Bernard et al. 2021 |
| Lahar physics (low viscosity) | 2D shallow-water + Bingham yield | Iverson & George 2014 |
| Lava physics (high viscosity) | D8 + stochastic particle advection | inspired by [fluidFlow](https://github.com/fakmalpradana/fluidFlow), MrLavaLoba |

The solver selection is driven by `kind` on the [material profile](./materials.ts): `lahar` → SWE, `lava` → D8. Each profile additionally carries `laharzA` and `laharzB` so the empirical envelope shifts with material — this is the design's main novelty contribution.

## Volume triple → 3-level confidence

`hazardEnvelope({ min, likely, max }, profile)` returns three planimetric / cross-section pairs:

- **High probability** (smallest footprint) ← V_min
- **Medium probability** ← V_likely
- **Low probability** (largest footprint) ← V_max

This mirrors Schilling 2014's LDZCL approach used inside PEARPY.

## Bingham yield-stress term

The SWE solver in [`sim/swe-solver.ts`](./sim/swe-solver.ts) zeros momentum on cells where the bed shear stress

```
τ = ρ · g · h · |∇(z + h)|
```

falls below the material's yield strength `τ_y`. This produces the realistic "lahar stops on low slopes" behaviour that distinguishes a debris flow from pure water and is the main physical departure from the base [fluidFlow](https://github.com/fakmalpradana/fluidFlow) engine.

## Current limitations of the test dataset

- The Kelud 2014 heightmap is **synthetic** (Gaussian cone matching Kelud's 1731 m summit), generated by the OpenTopography fallback in [`scripts/lahar/bake-srtm.ts`](../../scripts/lahar/bake-srtm.ts) because the public demo API key is rate-limited. Set `OPENTOPO_KEY` to use real SRTM 1-arc-second.
- Deposition polygon and proximal hazard cone are **synthetic circles** (radii 1.3 km and 2.8 km from summit). They will be replaced when the kantor PEARPY outputs are published to the bucket — the `LaharDataRef` schema in [`types.ts`](./types.ts) is bucket-ready (just point `baseUrl` to the bucket path).
- LAHARZ envelope is rendered as **area-equivalent circles** around the LSP, not as channel-following polygons. Channel-following polygons require PEARPY's `LDZCL` raster output.
- Only **Mt. Kelud 2014** has a `laharData` field today. Mt. Agung (paper's original study site) can be added later by populating its own `laharData` bucket path.

## Reference engine

Animated propagation patterns and the SWE / D8 dual-solver architecture are adapted from [`fakmalpradana/fluidFlow`](https://github.com/fakmalpradana/fluidFlow), with the Bingham yield term and material-dependent LAHARZ coefficients added on top.
